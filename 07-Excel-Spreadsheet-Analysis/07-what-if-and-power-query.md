# What-If Analysis and Power Query Basics

## Definition

**What-if analysis** tests how a result changes when an input changes. In Excel, BAs mostly use a **driver cell** (return rate, fee, volume) and a simple model; **Goal Seek** finds the input that hits a target; **Scenario Manager** stores named input sets. **Power Query** (Get & Transform) is the ETL inside Excel: connect to CSV/folders, **append** files, **merge** tables, **unpivot** columns, clean, load to a Table.

You are not building a full financial model. You are answering "if returns fall 2%, what happens to margin?" and "can I stack three branch files every month?"

## Why it matters

POs ask for impact before a story is sized. Ops send monthly extracts in different shapes. Doing that by hand for 12 months is how numbers drift.

## Goal Seek and scenario-lite for BAs

Simple ShopEase margin model (inputs in yellow cells):

| Cell | Name | Example |
|---|---|---|
| B2 | `Gmv` | 10000000 |
| B3 | `ReturnRate` | 0.08 |
| B4 | `UnitMarginPct` | 0.18 |
| B5 | `ReturnCostPct` | 0.40 |

```excel
=B2*(1-B3)*B4 - B2*B3*B4*B5
```

That is: margin on kept GMV minus lost margin and extra cost on returns (tune the formula with finance; this is a teaching sketch).

**Question:** if return rate falls 2 percentage points (8% → 6%), extra margin?

Copy the block; set `ReturnRate` = 0.06; difference vs base. Or:

```excel
=BaseMargin - NewMargin
```

**Goal Seek:** Data → What-If → Goal Seek. Set margin cell to a target (e.g. 1,500,000) by changing `ReturnRate`. Use this in a workshop: "We need return rate at X% to hit the margin goal." Then ask whether that X% is feasible — Goal Seek does not make it true.

**Scenario Manager:** Scenario `Base` (8%), `Stretch` (6%), `Risk` (10%). Summary sheet for the PO. Keep it to 3–4 inputs or nobody trusts it.

Do not Goal Seek five variables at once. You will get a mathematically pretty, operationally impossible mix.

## Power Query: BA uses

| Need | PQ action |
|---|---|
| Monthly vendor CSV | Data → From File → From CSV / From Folder |
| Three branches, same columns | Append queries |
| Different column names | Rename in PQ so they match, then append |
| City in columns Jan–Dec | Unpivot Other Columns → `Month`, `Value` |
| Rates in another file | Merge (Left Outer) on City code |
| Trim, types, filter junk rows | Transform before Load |

**From Folder:** point at `NovaBank\NPA\2026\`. Combine files. New month = drop file in folder → Refresh.

**Unpivot:** if ShieldSure sends products as columns, unpivot to `Product`, `Premium` so you can pivot properly.

**Merge:** `Orders` Left Outer merge `Sellers` on `SellerId` — same idea as SQL LEFT JOIN. Check unmatched (null city).

**Append:** stack Branch A/B/C after each has the same 8 column names.

Load To: Table on sheet `npa_all`. Keep Query as the recipe. Do not 40 copies of paste.

Sample M is generated by the UI; you should recognise steps: Source → Promote Headers → Changed Type → Filtered Rows → Appended Query.

## Real-world examples

1. **QuickBite**: vendor payout CSVs weekly; From Folder + filter `status <> test`.
2. **ShopEase**: Goal Seek on ads spend to hit a GMV target — then marketing validates if spend is possible.

## Scenario / Use case

NovaBank risk sends monthly NPA extracts from three branches. Formats differ:

| Branch | File | Quirk |
|---|---|---|
| Pune | `NPA_PNQ_Aug.xlsx` | Headers on row 1, amount in lakhs |
| Delhi | `del_npa_aug.csv` | Headers on row 3, amount in rupees, extra `Remarks` |
| Chennai | `MAS-NPA-2026-08.xls` | `NPA_Amt` vs `Amount`, date as text |

BA Power Query plan:

1. Three queries: skip 2 rows on Delhi; rename `NPA_Amt` → `Amount`; multiply Pune by 100000.
2. `Changed Type` on `Amount` to Decimal, `AsOf` to Date.
3. Add column `Branch` = Pune/Delhi/Chennai.
4. Append to `NPA_All`.
5. Merge with `AccountMaster` on `AccountId` to flag orphans.
6. Load; pivot NPA by branch and product.

First month takes two hours. Next month: replace files, Refresh All, recon count vs email "row counts 401 / 288 / 156". Unmatched accounts become a Jira story: "branch extract missing CIF".

What-if on the same workbook: if 5% of Watchlist migrates to NPA, extra NPA stock — a driver cell, not a fantasy model.

## Weak vs strong

| Weak | Strong |
|---|---|
| Paste 3 files under each other | Append in Power Query |
| Edit cells inside the load table | Edit the query |
| Goal Seek as a promise | Goal Seek as a discussion number |
| 12 what-if copies of the whole workbook | Scenarios or one input panel |
| Ignore lakhs vs rupees | Convert in PQ, document unit |
| Unpivot by deleting columns by hand | Unpivot Other Columns |

## Notes

- Power Query refresh needs the file path; if the vendor changes the layout, the query fails — that is a useful alarm.
- Record units (INR vs lakhs) on the dashboard.
- What-if is not UAT. It does not prove the story will ship.
- Disable "Enable load" on staging queries; load only the final table.
- Privacy levels can block merges of internal files; set correctly with IT, do not screenshot data into a new book as a workaround for PII.
- Keep raw files immutable in a `inbox` folder.
- If the company has a warehouse, PQ is a bridge — say when the metric should move to SQL/BI.
